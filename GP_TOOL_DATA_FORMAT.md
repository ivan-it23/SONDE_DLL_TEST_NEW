# GP_TOOL_DATA — Структура данных и форматы файлов

Документ описывает canonical-структуру данных `GP_TOOL_DATA`, форматы файлов `.bin`, `.biv`, `.DEV`, логику сигнатуры и полный pipeline чтения данных в приложении **AMK-Horizon-New-Chart**.

---

## 1. Canonical-структура `GP_TOOL_DATA`

Все приборы компании (AUTONOM и LWD) передают данные в единой canonical-структуре размером **240 байт**. Структура объявлена в `ToolDataTypes.h` с выравниванием `#pragma pack(push, 1)` — без padding-байтов.

```cpp
#pragma pack(push, 1)
struct GP_TOOL_DATA {
    uint32_t signature;       // 4 байта
    uint32_t condition;       // 4 байта
    uint32_t frame;           // 4 байта
    float    temperature;     // 4 байта
    float    rho_smt[2][5];   // 40 байт
    float    phase_smt[2][5]; // 40 байт
    float    AM_RX_1[2][5];   // 40 байт
    float    ZERO_AM_RX_1[2]; // 8 байт
    float    AM_RX_2[2][5];   // 40 байт
    float    ZERO_AM_RX_2[2]; // 8 байт
    float    DELTA_PH[2][5];  // 40 байт
    float    ZERO_dPH[2];     // 8 байт
};                            // Итого: 240 байт
#pragma pack(pop)
```

Компилятор проверяет размер статическим утверждением:

```cpp
static_assert(sizeof(GP_TOOL_DATA) == 240, "GP_TOOL_DATA must be exactly 240 bytes");
```

## 2. Описание полей

### 2.1. Служебные поля

| Поле | Тип | Размер | Описание |
|---|---|---|---|
| `signature` | `uint32_t` | 4 байта | Уникальный идентификатор кадра. Содержит закодированный `toolCode` — тип и модификацию прибора. Используется для автоматического определения типа прибора при парсинге. |
| `condition` | `uint32_t` | 4 байта | Битовая маска состояния передатчиков. Каждый бит — работоспособность соответствующего передатчика в данный момент. |
| `frame` | `uint32_t` | 4 байта | Порядковый номер кадра. Монотонно возрастает на протяжении записи. |
| `temperature` | `float` | 4 байта | Температура прибора (°C) в момент записи кадра. |

### 2.2. Двумерные массивы измерений `[freqIdx][txIdx]`

Все массивы измерений индексируются одинаково:

- **`freqIdx = 0`** → частота **400 кГц**
- **`freqIdx = 1`** → частота **2000 кГц**
- **`txIdx = 0..4`** → передатчики **T1..T5**

> **Важно:** Для 4-передатчикового прибора (например, LWD 4Tx) используются только слоты `txIdx = 0..3` (T1–T4). Слот `txIdx = 4` не заполняется и не должен читаться. Активное число передатчиков определяется из `ToolCapabilities.transmitterCount`.

| Поле | Размер | Единицы | Описание |
|---|---|---|---|
| `rho_smt[2][5]` | 40 байт | Ом·м | Симметризованное удельное электрическое сопротивление (УЭС), вычисленное прибором или на компьютере. |
| `phase_smt[2][5]` | 40 байт | рад | Симметризованная разность фаз. Результат применения матрицы симметризации к `DELTA_PH`. |
| `AM_RX_1[2][5]` | 40 байт | отн.ед. | Амплитуда сигнала на приёмнике RX1 для каждого передатчика. |
| `AM_RX_2[2][5]` | 40 байт | отн.ед. | Амплитуда сигнала на приёмнике RX2 для каждого передатчика. |
| `DELTA_PH[2][5]` | 40 байт | рад | Сырая разность фаз RX2 − RX1 для каждого передатчика. |

### 2.3. Silent-каналы (молчащие передатчики)

Silent-каналы хранятся **отдельно** от основных массивов — в выделенных полях, индексируемых только по частоте (`freqIdx`).

| Поле | Размер | Описание |
|---|---|---|
| `ZERO_AM_RX_1[2]` | 8 байт | Амплитуда на RX1 при молчащем передатчике (опорный уровень шума). Индекс: `[freqIdx]`. |
| `ZERO_AM_RX_2[2]` | 8 байт | Амплитуда на RX2 при молчащем передатчике. Индекс: `[freqIdx]`. |
| `ZERO_dPH[2]` | 8 байт | Разность фаз RX2 − RX1 при молчащем передатчике (опорный фазовый сдвиг). Индекс: `[freqIdx]`. |

## 3. Декодирование поля `signature`

Поле `signature` одновременно выполняет две функции: идентифицирует кадр и кодирует тип прибора.

### 3.1. Извлечение `toolCode`

```cpp
// Нижние 20 бит signature делятся на 1000
uint32_t toolCode = ((signature << 12) >> 12) / 1000u;
```

### 3.2. Декодирование `toolCode = XYZ`

`toolCode` — трёхзначное число вида `XYZ`:

| Цифра | Позиция | Значение |
|---|---|---|
| **X** — сотни | тип прибора | `1` = Автономный (AUTONOM), `2` = LWD |
| **Y** — десятки | число передатчиков | `3`, `4` или `5` |
| **Z** — единицы | модификация прибора | `1`, `2`, ... |

**Примеры известных `toolCode`:**

| `toolCode` | Тип прибора | Передатчики | Модификация |
|---|---|---|---|
| `151` | AUTONOM | 5 | 1 |
| `152` | AUTONOM | 5 | 2 (SDR) |
| `241` | LWD | 4 | 1 |
| `231` | LWD | 3 | 1 |

Реализация декодирования находится в `ToolDataAdapters.cpp`:

```cpp
DeviceType DetermineDeviceType(uint32_t toolCode) {
    // Сотня (1 = AUTONOM, 2 = LWD)
    switch (toolCode / 100u) {
        case 1: return DeviceType::AUTONOM;
        case 2: return DeviceType::LWD;
        default: return DeviceType::UNKNOWN;
    }
}

int DetermineTransmitterCount(uint32_t toolCode) {
    // Десятки: число передатчиков (3–5)
    return (toolCode / 10u) % 10u;
}
```

## 4. Форматы файлов

Приложение поддерживает три формата файлов. Все они хранят последовательность кадров `GP_TOOL_DATA` — разница только в наличии служебного заголовка на каждый кадр.

### 4.1. Формат `.bin`

Файл — непрерывная последовательность кадров по **240 байт** без заголовков.

```
┌──────────────┬──────────────┬──────────────┬ ...
│ GP_TOOL_DATA │ GP_TOOL_DATA │ GP_TOOL_DATA │
│  240 байт    │  240 байт    │  240 байт    │
└──────────────┴──────────────┴──────────────┘
```

- Размер файла кратен **240** байт.
- `signature` читается с байта **0** первого кадра.

### 4.2. Формат `.biv`

Технически идентичен `.bin`: те же **240 байт** на кадр без служебных заголовков. Расширение используется для разграничения типов сессий на уровне именования файлов.

### 4.3. Формат `.DEV`

Каждый кадр содержит **11-байтный заголовок**, за которым следует **240 байт** полезной нагрузки (`GP_TOOL_DATA`). Физический размер одного кадра — **251 байт**.

```
┌─────────────────────────────────────────────────────────
│  Кадр 1 (251 байт)
│  ┌─────────────────┬──────────────────────────────────┐
│  │  Заголовок DEV  │       GP_TOOL_DATA               │
│  │    11 байт      │         240 байт                 │
│  └─────────────────┴──────────────────────────────────┘
├─────────────────────────────────────────────────────────
│  Кадр 2 (251 байт)
│  ...
```

- Размер файла кратен **251** байт.
- `signature` читается с байта **11** (после пропуска заголовка) первого кадра.

## 5. Pipeline чтения файла

Ниже описана полная последовательность действий при открытии файла в приложении.

### Шаг 1. Определение формата

```
Расширение файла → FileFormat
  .bin  → FORMAT_BIN
  .biv  → FORMAT_BIV
  .DEV  → FORMAT_DEV
  иное  → FORMAT_UNKNOWN → ❌ отказ
```

### Шаг 2. Чтение сигнатуры

```
FORMAT_BIN / FORMAT_BIV:  читать uint32_t с offset = 0
FORMAT_DEV:               читать uint32_t с offset = 11
```

Реализовано в `DataModule::ReadFileSignature()` (`DataModule.cpp`, строка 230).

### Шаг 3. Поиск адаптера

По прочитанной `signature` вычисляется `toolCode`, после чего `ToolDataAdapterRegistry` ищет подходящий адаптер. Сейчас в реестре зарегистрирован единственный адаптер — `UniversalCanonicalAdapter`, который обрабатывает любой корректный `toolCode > 0`.

### Шаг 4. Проверка файла

```
Файл принимается, если одновременно:
  ✓ Расширение поддерживается
  ✓ Адаптер найден по signature
  ✓ Адаптер поддерживает данный формат контейнера
  ✓ Размер файла кратен физическому размеру кадра
       (240 для .bin/.biv, 251 для .DEV)
```

### Шаг 5. Последовательное чтение кадров

Для каждого кадра `n`:

```
offset = n × physicalFrameSize

Для FORMAT_DEV:
  seekg(offset + 11)     // пропуск заголовка DEV
Для FORMAT_BIN / FORMAT_BIV:
  seekg(offset)

read(buffer, 240)        // читаем ровно 240 байт
```

### Шаг 6. Парсинг кадра

```
ParseRawFrameDetailed(buffer, 240)
  ↓
memcpy → GP_TOOL_DATA
  ↓
toolCode = DecodeToolCode(signature)
  ↓
kind = DetermineKindFromToolCode(toolCode)    // AUTONOM или LWD
  ↓
capabilities = BuildCapabilities(toolCode)    // transmitterCount и флаги
  ↓
ParsedToolFrame { kind, capabilities, canonicalData }
```

### Шаг 7. Сохранение результата

Каждый успешно разобранный кадр сохраняется как пара:
- `GP_TOOL_DATA` — данные измерений
- `ToolRecordMetadata` — метаданные (тип прибора, capabilities)

## 6. Работа с полями через `ToolDataAccessView`

Верхние слои приложения не обращаются к полям `GP_TOOL_DATA` напрямую, а используют вспомогательный класс `ToolDataAccessView` (`ToolDataAccess.h`). Он учитывает `ToolCapabilities` и не позволяет читать данные для несуществующих передатчиков.

```cpp
ToolDataAccessView view(record, metadata);

float val;
// Безопасное чтение разности фаз для T1 на 400 кГц
if (view.TryGetDeltaPhase(0, 0, val)) { /* val содержит DELTA_PH[0][0] */ }

// Безопасное чтение амплитуды RX2 для T3 на 2000 кГц
if (view.TryGetAmplitudeRx2(1, 2, val)) { /* val содержит AM_RX_2[1][2] */ }
```

**Доступные методы:**

| Метод | Источник в `GP_TOOL_DATA` |
|---|---|
| `TryGetDeltaPhase(freqIdx, txIdx, out)` | `DELTA_PH[freqIdx][txIdx]` |
| `TryGetAmplitudeRx1(freqIdx, txIdx, out)` | `AM_RX_1[freqIdx][txIdx]` |
| `TryGetAmplitudeRx2(freqIdx, txIdx, out)` | `AM_RX_2[freqIdx][txIdx]` |
| `TryGetPhaseSmt(freqIdx, txIdx, out)` | `phase_smt[freqIdx][txIdx]` |
| `TryGetRhoSmt(freqIdx, txIdx, out)` | `rho_smt[freqIdx][txIdx]` |
| `TryGetSilentAmplitudeRx1(freqIdx, out)` | `ZERO_AM_RX_1[freqIdx]` |
| `TryGetSilentAmplitudeRx2(freqIdx, out)` | `ZERO_AM_RX_2[freqIdx]` |
| `TryGetSilentDeltaPhase(freqIdx, out)` | `ZERO_dPH[freqIdx]` |
| `GetTemperature()` | `temperature` |

Все `TryGet*`-методы возвращают `false`, если данные недоступны (нет capability, неверный индекс).

## 7. Единицы измерения при отображении

Значения в структуре хранятся в нативных единицах прибора. При отображении на графиках верхний слой применяет следующие преобразования:

| Данные | Преобразование | Единицы на графике |
|---|---|---|
| `AM_RX_1`, `AM_RX_2` | `value × 4000.0 / 2²⁴` | мВ |
| `DELTA_PH`, `phase_smt` | `NormalizePhase(value) × 57295.7795` | мГрад (mdeg) |
| `rho_smt` | без преобразования | Ом·м |
| `temperature` | без преобразования | °C |

## 8. `ToolCapabilities` — как используется

После парсинга каждый кадр сопровождается структурой `ToolCapabilities`. Она определяет, какие поля `GP_TOOL_DATA` реально заполнены для данного прибора.

| Флаг | Значение `true` |
|---|---|
| `transmitterCount` | Число активных передатчиков (3, 4 или 5) |
| `hasT5` | Доступен T5 (только для 5Tx приборов) |
| `hasDeltaPhase` | Поле `DELTA_PH` содержит данные |
| `hasSondePhaseSmt` | `phase_smt` содержит симм. фазы с прибора |
| `hasSondeRhoSmt` | `rho_smt` содержит симм. УЭС с прибора |
| `hasZeroAmplitudeRx1` | `ZERO_AM_RX_1` содержит данные |
| `hasZeroAmplitudeRx2` | `ZERO_AM_RX_2` содержит данные |
| `hasZeroDeltaPhase` | `ZERO_dPH` содержит данные |
| `supportsDevContainer` | Прибор может записывать `.DEV`-файлы |
| `supportsComPolling` | Прибор поддерживает опрос по COM-порту |

## 9. Быстрая шпаргалка

```
Файл .DEV:
  Кадр = 11 байт (заголовок DEV) + 240 байт (GP_TOOL_DATA)
  Всего: 251 байт/кадр

Файл .bin / .biv:
  Кадр = 240 байт (GP_TOOL_DATA), без заголовка

GP_TOOL_DATA:
  [0..3]   signature (4 байта) — тип прибора закодирован здесь
  [4..7]   condition (4 байта) — битовая маска активных Tx
  [8..11]  frame     (4 байта) — порядковый номер кадра
  [12..15] temperature (4 байта)
  [16..55] rho_smt[2][5]   — УЭС (40 байт)
  [56..95] phase_smt[2][5] — симм. фазы (40 байт)
  [96..135] AM_RX_1[2][5]  — амплитуды RX1 (40 байт)
  [136..143] ZERO_AM_RX_1[2] — silent RX1 (8 байт)
  [144..183] AM_RX_2[2][5] — амплитуды RX2 (40 байт)
  [184..191] ZERO_AM_RX_2[2] — silent RX2 (8 байт)
  [192..231] DELTA_PH[2][5] — разность фаз (40 байт)
  [232..239] ZERO_dPH[2]   — silent разность фаз (8 байт)

Индексация двумерных массивов:
  [0][0..N-1] — частота 400 кГц, передатчики T1..TN
  [1][0..N-1] — частота 2000 кГц, передатчики T1..TN
  N = transmitterCount (из ToolCapabilities)
```

## 10. Структура метрологии `METROLOGY_DATA`

Метрология — это калибровочные параметры конкретного экземпляра прибора. Она хранится в отдельном бинарном файле (`.bin`) и имеет тот же размер, что и кадр данных — **240 байт** (`#pragma pack(push, 1)`).

Структура объявлена в `SerialModule.h`:

```cpp
#pragma pack(push, 1)
struct METROLOGY_DATA {
    uint32_t signature;           // 4 байта
    uint32_t serial;              // 4 байта
    uint16_t L1[5];               // 10 байт
    uint16_t L2[5];               // 10 байт
    uint16_t F[2];                // 4 байта
    int16_t  Air_zz[2][5];        // 20 байт
    int16_t  Air_zz_amt[2][5];    // 20 байт
    uint32_t D_sonde_mm;          // 4 байта
    uint32_t work_type;           // 4 байта
    uint32_t Rx_Position;         // 4 байта
    uint16_t service[78];         // 156 байт (резерв)
};                                // Итого: 240 байт
#pragma pack(pop)
```

Корректность размера гарантируется статическим утверждением:

```cpp
static_assert(sizeof(METROLOGY_DATA) == 240, "METROLOGY_DATA must be exactly 240 bytes");
```

### 10.1. Описание полей `METROLOGY_DATA`

| Поле | Тип | Размер | Описание |
|---|---|---|---|
| `signature` | `uint32_t` | 4 байта | Идентификатор прибора. Декодируется так же, как `signature` в `GP_TOOL_DATA` — содержит `toolCode` с типом и числом передатчиков. |
| `serial` | `uint32_t` | 4 байта | Серийный номер конкретного экземпляра прибора. |
| `L1[5]` | `uint16_t[5]` | 10 байт | Расстояния от источника до ближнего приёмника RX1 для каждого передатчика T1–T5 (в мм). Используются в формулах расчёта УЭС. |
| `L2[5]` | `uint16_t[5]` | 10 байт | Расстояния от источника до дальнего приёмника RX2 для каждого передатчика T1–T5 (в мм). |
| `F[2]` | `uint16_t[2]` | 4 байта | Рабочие частоты прибора. `F[0]` = 400 кГц, `F[1]` = 2000 кГц (в единицах, согласованных с формулами). |
| `Air_zz[2][5]` | `int16_t[2][5]` | 20 байт | Калибровочные нули фазы по воздуху для каждой частоты и передатчика. Используются при симметризации: вычитаются из `DELTA_PH` перед применением матрицы симметризации. Индексация: `[freqIdx][txIdx]`. |
| `Air_zz_amt[2][5]` | `int16_t[2][5]` | 20 байт | Пороговые амплитуды по воздуху для каждой частоты и передатчика. Используются для определения работоспособности передатчиков: если амплитуда сигнала ниже порога — передатчик считается нерабочим. Индексация: `[freqIdx][txIdx]`. |
| `D_sonde_mm` | `uint32_t` | 4 байта | Диаметр зонда в мм. |
| `work_type` | `uint32_t` | 4 байта | Рабочий тип / режим прибора. |
| `Rx_Position` | `uint32_t` | 4 байта | Положение приёмников. `0` = R1→T1 (по умолчанию), `1` = R1→T2. |
| `service[78]` | `uint16_t[78]` | 156 байт | Резервные поля. Не используются в текущей логике приложения. |

### 10.2. Как `Air_zz` используется при расчёте

Поле `Air_zz` — ключевое при симметризации фаз. Логика (`variable.cpp` в `SONDE_DLL_NEW`):

```cpp
// Для каждого передатчика n нормализуем разность фаз к воздушному нулю:
for (int n = 0; n < 4; n++) {
    d_PH[n] = Data->DELTA_PH[freq][n];
    if (n & 1)  d_PH[n] -= (float)(metro->Air_zz[freq][n]) / 57297.0f;
    else        d_PH[n] = -d_PH[n] + (float)(metro->Air_zz[freq][n]) / 57297.0f;
}
// Затем результат phase_smt[freq][n] = K[n][*] * d_PH[*]
```

Поле `Air_zz_amt` используется для определения живых передатчиков:

```cpp
// Передатчик считается рабочим, если амплитуда > порога Air_zz_amt
if (AM_RX_2[freq][T1] * mV > metro->Air_zz_amt[freq][T1]) condition |= ...;
```

### 10.3. Формат файла метрологии

Файл метрологии — это ровно **240 байт** без каких-либо заголовков или обёртки:

```
┌──────────────────────────────────┐
│        METROLOGY_DATA            │
│           240 байт               │
└──────────────────────────────────┘
```

- Поддерживаемое расширение: `.bin`
- Размер файла должен быть **ровно 240 байт**
- Сигнатура (`signature`) читается с байта **0** (нет заголовка, нет смещения)

### 10.4. Pipeline чтения файла метрологии

Реализовано в `MetrologyModule::LoadFromFile()` (`MetrologyModule.cpp`):

```
1. Открыть файл в бинарном режиме

2. Прочитать первые 4 байта → uint32_t signature

3. Проверить signature через ToolDataAdapterRegistry::IsSupportedSignature()
   - Если toolCode == 0 → ❌ отказ с ошибкой

4. Перемотать в начало (seekg 0)

5. Прочитать ровно 240 байт → METROLOGY_DATA

6. Если прочитано < 240 байт → ❌ файл повреждён

7. ✅ Метрология загружена, currentFilePath сохраняется
```

Псевдокод на C++:

```cpp
uint32_t sig = 0;
f.read(&sig, 4);                                  // читаем signature
if (!IsSupportedMetrologyFileSignature(sig)) ...  // проверяем

f.seekg(0);                                       // перематываем в начало
METROLOGY_DATA tmp{};
f.read(&tmp, sizeof(tmp));                        // читаем 240 байт целиком
current = tmp;
```

### 10.5. COM-протокол: чтение и запись метрологии

Метрология также может быть запрошена с прибора по COM-порту (реализовано в `SerialModule`):

| Команда | Код | Описание |
|---|---|---|
| `CMD_GET_METROLOGY` | `0x13` | Запрос метрологии с прибора. Пустой payload (5 байт пакет). Прибор отвечает 240-байтной `METROLOGY_DATA`. |
| `CMD_SET_METROLOGY` | `0x13` | Запись метрологии на прибор. Payload = 240 байт `METROLOGY_DATA`. Прибор отвечает пустой квитанцией. |
| `CMD_SET_AIR` | `0x1A` | Команда авто-калибровки нулей по воздуху. Обновляет `Air_zz` и `Air_zz_amt` на приборе. |

> Команды чтения и записи метрологии используют одинаковый код `0x13`. Различие — в размере payload: пустой (5 байт пакет) = запрос, 240 байт = запись.

Формат пакета COM-протокола: `[CMD 1 байт][LEN 2 байта][PAYLOAD N байт][CRC16 2 байта]`

### 10.6. Быстрая шпаргалка по `METROLOGY_DATA`

```
Файл метрологии:
  240 байт, без заголовка
  signature с байта 0

Байтовые смещения METROLOGY_DATA:
  [0..3]    signature   (4 байта) — тип прибора, то же декодирование, что GP_TOOL_DATA
  [4..7]    serial      (4 байта) — серийный номер прибора
  [8..17]   L1[5]       (10 байт) — дистанции до RX1, мм
  [18..27]  L2[5]       (10 байт) — дистанции до RX2, мм
  [28..31]  F[2]        (4 байта) — рабочие частоты
  [32..51]  Air_zz[2][5]     (20 байт) — нули фаз по воздуху [freqIdx][txIdx]
  [52..71]  Air_zz_amt[2][5] (20 байт) — пороги амплитуд по воздуху [freqIdx][txIdx]
  [72..75]  D_sonde_mm  (4 байта) — диаметр зонда
  [76..79]  work_type   (4 байта) — тип работы
  [80..83]  Rx_Position (4 байта) — позиция приёмников
  [84..239] service[78] (156 байт) — резерв
```
