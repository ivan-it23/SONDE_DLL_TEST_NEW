# Документация проекта SONDE_DLL

## 1. Общее описание системы

Система предназначена для обработки, интерпретации и визуализации данных электромагнитного каротажа (ЭМК) с индуктивными зондами. Основная задача — по симметризованным фазам многокатушечного прибора определить параметры геологической среды: удельное электрическое сопротивление (УЭС) пласта `Ro_p`, УЭС зоны проникновения `Ro_zp` и радиус зоны проникновения `R_zp`.

Система состоит из пяти взаимосвязанных проектов:

| Проект | Расположение | Назначение |
|--------|-------------|------------|
| **SONDE_DLL_TEST_NEW** | `C:\Users\Admin\Desktop\SONDE_DLL_TEST_NEW` | Тестовое приложение с графиками |
| **SONDE_DLL_NEW** | `C:\Users\Admin\Desktop\SONDE_DLL_NEW` | C++ DLL с расчётными алгоритмами |
| **neuro-weights** | `C:\Users\Admin\Desktop\SONDE_DLL_TEST_NEW\x64\Release\neuro-weights` | Координатор весов нейросети по типам приборов |
| **symmetrized_versions** | `C:\Users\Admin\Desktop\symmetrized_versions` | Python-проект обучения PINN и экспорта весов |
| **NEURO_3COIL_Rop_Rozp_Rzp_DLL** | `C:\Users\Admin\source\repos\NEURO_3COIL_Rop_Rozp_Rzp_DLL` | C++ DLL-реализация нейросети (NEURO_TEST.dll) |

## 2. SONDE_DLL_TEST_NEW — тестовое приложение

### 2.1. Назначение

Графическое тестовое приложение на C++/CLI (Windows Forms) для визуальной проверки алгоритмов DLL. Читает файлы данных `.DEV` и сырые `.bin`, загружает `SONDE_DLL_1.0.dll`, вызывает экспортируемые функции DLL и строит 11 графиков.

При каждом запуске приложение использует жёстко заданные в `SONDE_1.0.cpp` файлы метрологии и данных. В меню **Файл** можно временно выбрать другие файлы и повторно запустить тестирование клавишей **F5**. Выбор хранится только до закрытия процесса и не изменяет значения по умолчанию в исходном коде.

### 2.4. Выбор и проверка входных файлов

Перед обработкой приложение вызывает `sonde_set` для выбранной метрологии, затем `get_data_file_info` для файла данных. DLL определяет размер служебной части записи по расширению, проверяет целостность файла и сигнатуру **каждого** кадра:

| Формат данных | Размер записи | Смещение `GP_DATA` |
|---------------|----------------|--------------------|
| `.DEV` | 251 байт | 11 байт |
| `.bin` | 240 байт | 0 байт |

Если сигнатура данных не совпадает с сигнатурой метрологии или внутри файла встретились кадры разных приборов, обработка прекращается и пользователь получает сообщение о том, что файлы относятся к разным приборам.

```cpp
int sonde_set(const char *Metrology, const char *reserved) {
    // 1. Чтение .bin файла метрологии
```

```cpp
ID get_sonde_id(uint32_t signature) {
    uint32_t buff = signature << 12;
    buff = buff >> 12;
    tool.type_ = buff / 100000;
    tool.N_Tx = (buff % 100000) / 10000;
    tool.mod = (buff % 10000) / 1000;
```

### 3.7. Нейросетевой расчёт (`calculate_Rho_AF`)

```cpp
// C:\Users\Admin\Desktop\SONDE_DLL_NEW\SONDE_DLL_1.0\SONDE_DLL_1.0.cpp:98-200
extern "C" __declspec(dllexport) int calculate_Rho_AF(...) {
    // 1. УЭС по зондам методом RO_dFI
    for (int freq = 0; freq < 2; freq++)
        for (int Tx = 0; Tx < 4; Tx++)
            Ro_3c->Ro[freq][Tx] = RO_dFI(param[freq][Tx], Phase->Phase[freq][Tx]);
    
    // 2. Подготовка входов нейросети
    float raw_inputs[8];
    for (int Tx = 0; Tx < 4; Tx++) {
        raw_inputs[Tx] = phase[0][Tx] * Grad;       // 400 кГц, рад → град
        raw_inputs[Tx + 4] = phase[1][Tx] * Grad; // 2000 кГц, рад → град
    }
    
    // 3. Вызов нейросети
    float out_results[3];
    neuro_predict(raw_inputs, out_results);
    
    // 4. Распределение результатов
    // out_results[0] = r_inv (м)   → R_zp (см)
    // out_results[1] = rho_inv     → Ro_zp
    // out_results[2] = rho_form     → Ro_p
    for (int freq = 0; freq < 2; freq++) {
        Ro_3c->Ro_p[freq] = rho_form;
        Ro_3c->Ro_zp[freq] = rho_inv;
        Ro_3c->R_zp[freq] = r_inv_m * 100.0f;
    }
}
```

```cpp
// C:\Users\Admin\source\repos\NEURO_3COIL_Rop_Rozp_Rzp_DLL\NEURO_TEST\NEURO_TEST.cpp
class GeoInversionNet {
    Matrix W1, W2, W3, W4;           // 512×32, 1024×512, 512×1024, 3×512
    Eigen::VectorXf b1, b2, b3, b4;
    Eigen::VectorXf X_mean, X_scale;   // StandardScaler
    Eigen::VectorXf Y_min, Y_scale;    // MinMaxScaler

    Eigen::VectorXf predict(const Eigen::VectorXf& X_raw) {
        // 1. Нормализация входов
        Eigen::VectorXf X = (X_raw - X_mean).cwiseQuotient(X_scale);
        // 2. Проход через сеть
        Eigen::VectorXf h1 = W1 * X + b1; apply_gelu(h1);
        Eigen::VectorXf h2 = W2 * h1 + b2; apply_gelu(h2);
        Eigen::VectorXf h3 = W3 * h2 + b3; apply_gelu(h3);
        Eigen::VectorXf Y_pred_scaled = W4 * h3 + b4;
        // 3. Обратное преобразование
        Eigen::VectorXf Y_log = (Y_pred_scaled - Y_min).cwiseQuotient(Y_scale);
        // 4. Физические ограничения и pow10
        Y_phys(0) = pow(10, log_r_inv) - 1e-4 + 0.06;  // r_inv, м
        Y_phys(1) = pow(10, log_rho_inv);               // rho_inv, Ом·м
        Y_phys(2) = pow(10, log_rho_form);              // rho_form, Ом·м
        return Y_phys;
    }
};
```

## 9. Алгоритм обработки одного кадра

```
1. Чтение кадра GP_DATA (240 байт) из .DEV файла
   ↓
2. Валидация сигнатуры кадра (frame_signature == global_signature)
   ↓
3. Извлечение готовых данных:
   - phase_express = gp.phase_smt
   - ro_express = gp.rho_smt
   - phase = gp.DELTA_PH - Air
   ↓
4. Симметризация фаз: phase_smt = simmetry(phase, condition)
   ↓
5. Расчёт УЭС по зондам: ro_AF.Ro = RO_dFI(param, phase_express)
   ↓
6. Нейросетевой расчёт параметров зоны:
   raw_inputs[8] = phase_express * Grad
   out[3] = neuro_predict(raw_inputs)
   ro_AF.Ro_p = out[2]
   ro_AF.Ro_zp = out[1]
   ro_AF.R_zp = out[0] * 100 (см)
   ↓
7. Дополнительно:
   - ph_smt_zp(ro_AF, phase_zp) — модельные фазы с учётом зоны
   - ph_smt_ro(ro_AF, phase_pen) — фазы по вычисленным УЭС
   ↓
8. Добавление точек на графики 1-11
```

## 10. Важные замечания

1. **Коррекция за скважину не применяется к входам нейросети**: модель PINN обучена без учёта зоны проникновения.

2. **Ro_p едино для обеих частот**: нейросеть возвращает одно значение `rho_form`, которое записывается в `Ro_p[0]` и `Ro_p[1]`.

3. **R_zp в сантиметрах**: нейросеть возвращает радиус в метрах, в структуре `Ro` он хранится в сантиметрах.

4. **Поддерживаемые нейросетью приборы**: семейство LWD с четырьмя передатчиками и картограф в режиме LWD с четырьмя передатчиками. Полная сигнатура и номер прибора не хардкодятся.

5. **Паллетки не используются**: текущая обработка параметров зоны построена на нейросетевой логике. Второй аргумент `sonde_set` зарезервирован и равен `nullptr`.

6. **Производительность**: `Vzz_inf_cyl` — тяжёлый численный интеграл. Для больших файлов используйте кэширование или прореживание кадров.

### 10.1. Сверка с прошивками приборов

Проверены исходные тексты `main_AUTO_5Tx.txt` и `main_LWD_1DDS` из корня тестового проекта.

- Обе прошивки формируют `GP_DATA`, записывают в кадр `METROLOGY_data.signature`, `condition` и номер кадра, а затем передают пакет длиной 245 байт: 3 байта протокольного заголовка, 240 байт `GP_DATA` и 2 байта CRC16.
- Сырые файлы данных `.bin`, принимаемые приложением, содержат только последовательность 240-байтовых `GP_DATA`. Протокольные 3 байта и CRC в такой файл входить не должны.
- Служебные 11 байт записи `.DEV` относятся к контейнеру/регистратору, а не к структуре прошивки. Поэтому для `.DEV` используется смещение 11, для `.bin` — смещение 0.
- Геометрия LWD по умолчанию в прошивке (`L1`, `L2`, частоты и четыре передатчика) совпадает с `Metrology.bin`. Если поле диаметра в файле метрологии равно нулю, DLL теперь выбирает 120 мм для LWD и 90 мм для автономного прибора — в соответствии с константами прошивок.
- Сигнатура LWD по умолчанию `242106` совпадает с `Metrology.bin`. У AUTO-прошивки сигнатура по умолчанию `151001`, а в `metro_autonm_5Tx.bin` записана `151501`. Это не конфликт, если прибор загрузил метрологию из Flash: прошивка использует Flash и обращается к значению по умолчанию только при `0xFFFFFFFF`. Если Flash не прошит, DLL намеренно отклонит такую пару как относящуюся к разным приборам.
- Файл `autonom_5Tx.DEV` содержит полные записи по 251 байту, но заканчивается неполным 16-байтовым фрагментом следующей записи. Строгая проверка структуры считает такой файл усечённым. Автономный прибор при этом не допускается к нейросетевому расчёту.
